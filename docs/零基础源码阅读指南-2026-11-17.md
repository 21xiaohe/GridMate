## 怎么读这些注释

先读每个文件顶部的“本文件作用”和“建议读法”，再读一条具体调用链。不要一次从头背完整个仓库。

Python按逻辑语句加说明：函数、分支、循环、赋值、调用、异常与返回都有对应解释；跨多行的一条表达式放在起始位置解释。已有明确说明的语句保留原注释。纯括号、提示词正文、SQL字符串和测试数据不会强行逐字符插入注释，以免改变实际输入。

网页包含HTML、CSS、JavaScript，分别使用 `<!-- -->`、`/* */`、`//` 注释。学习说明只存在于源码，不显示在产品页面。

部分历史模块文档包含旧功能或旧实验描述，文件顶部已加入“阅读校正”。以当前可执行函数与有证据的验收报告为准，不把历史文字中的数字直接背成简历成绩。

## 第一个可手工走通的例子

问题：“线路1在2025年6月停了几次电？”

1. 网页发送 `session_id` 和 `query` 到 `/api/chat`。
2. `agent.chat()`读取历史；首轮没有历史就不调用补全模型。
3. `agent.run()`固定数据版本，模型选择统计工具。
4. `query_outage_stat()`把完整问题交给 `ask()`。
5. 模型可能提取 `line_outage_count`、线路1、2025-06-01到2025-07-01。另一个等价模板是时间计数加线路过滤，并非只能选唯一模板。
6. 程序检查模板、线路、日期和可用范围，再执行参数化SQL。
7. 合成演示数据中结果为2次；事件按ID去重。这里的数字不适用于真实业务副本。
8. 工具返回数字、来源、范围、数据版本；模型据此回答，随后检查回答是否忠于证据。
9. 成功且未降级时，程序成对保存本轮问答；网页展示回答与来源。

练习时每一步写下输入、输出和下一步调用的函数名。能沿着这一条问题讲完，比先背全部库名更有用。

## 容易卡住的语法

| 写法 | 含义 |
| --- | --- |
| `def f(...)` / `return` | 定义函数；返回结果并结束当前调用 |
| `async def` / `await` | 定义可等待的异步函数；等待网络等操作时允许其他任务运行，不会自动加速模型生成 |
| `a: str` / `str \| None` | 类型提示；字符串，或字符串/空值二选一；普通Python类型提示不自动检查，Pydantic模型会做解析校验 |
| `list[dict]` | 一个列表，每项是字典 |
| `d['key']` / `d.get('key', default)` | 按键取值；前者缺键抛异常，后者缺键返回默认值 |
| `x or fallback` | 返回第一个真值；若x为空/假则返回fallback，不一定返回布尔值 |
| `[f(x) for x in rows if ...]` | 遍历、按条件过滤并收集结果，等价于一段循环 |
| `*args` / `**kwargs` | 接收或展开位置参数/关键字参数；字典里的 `**d` 表示展开字段 |
| `@decorator` | 注册或包装下方函数，例如HTTP路由、工具或固定快照；不是现在就执行一次模型调用 |
| `with` / `async with` | 管理进入与退出步骤；可能管理文件、事务、锁或请求上下文，具体看对象实现 |
| `try` / `except` / `finally` | 尝试执行、处理异常、无论成功失败都做清理 |
| `prompt \| model` | LangChain重载了竖线运算，表示先填提示词再调用模型；不是Python对任意对象都具有此含义 |
| `assert` / `pytest.fixture` | 测试要求某条件成立；测试准备对象由pytest注入，不属于线上业务逻辑 |

## 哪些脚本先读，哪些可以直接运行

从项目根目录运行 `.venv/Scripts/python.exe -m pytest -q` 是离线回归：使用合成数据和模型替身，并拦截外部网络。它检查代码约束，不评估真实模型质量。

`scripts/accept_*` 和 `scripts/eval_*` 是验收/评测入口，部分会调用真实服务、消耗额度或创建测试集合。文件顶部说明了依赖性质。先读命令行参数和报告规则，再按文档运行。

`scripts/query/publish.py`、`build_db.py`、`vectorize_events.py` 和数据加工脚本会写入文件或数据服务。为了理解代码，不需要在业务副本重新发布一次；已有独立合成副本可以演练。

`tests/fixtures/relevance_cases.json`是JSON数据文件，不支持注释。本次没有把中文注释塞进JSON；标签规则在 `tests/test_relevance.py`、`scripts/accept_relevance.py` 与相关性复盘中解释。

## 修改与验证边界

注释覆盖后端Python、数据脚本、验收脚本、测试、网页和依赖配置。没有编辑`.env`、真实台账或模型提示词内容。

当时的注释校验对比了注释前后的Python抽象语法树、有效词法单元和字符串，确认解释性文字没有改变执行逻辑；当时网页移除新增注释后与原文件一致，TOML解析结果一致。验收结果和原文件副本保存在被Git忽略的 `data/evaluations/annotations_20261117/`。之后的前端主题改版有实际布局和交互变化，使用独立的浏览器验收报告，不再对新版网页声称仅修改注释。

原有真实链路报告保留其当时源码哈希；新增注释使文件字节哈希改变，不应覆盖旧报告。本次通过逻辑一致性检查建立关联，不把以前的真实调用冒充为注释后新跑的真实模型测试。
